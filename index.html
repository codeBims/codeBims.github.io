Case file 03Analisis data · 2026

Studi kasus publik

Analisis transaksi

Online Retail

Saya memeriksa 541.909 baris transaksi untuk mencari tahu berapa banyak pelanggan yang punya invoice lain dalam 90 hari setelah invoice pertama yang terlihat di data.

42,7%

885 dari 2.075 pelanggan pada kohort Januari–Juni 2011 memiliki invoice non-pembatalan berikutnya dalam 90 hari.

Proses
Saya memeriksa data kosong, pembatalan, nilai nonpositif, dan baris identik sebelum membentuk kohort dengan SQL.
Temuan
Proporsi invoice lanjutan berbeda menurut bulan dan kelompok nilai invoice pertama.
Batasan
Ini mengukur aktivitas invoice, bukan retensi pembelian bersih. Pembatalan dan retur belum sepenuhnya dipasangkan dengan invoice asal.
  • Python
  • Pandas
  • SQLite
  • Matplotlib

Catatan privasi. Tangkapan layar daftar dashboard ini ditampilkan dengan izin. Data log, nama host, dan isi dashboard internal tetap tidak saya publikasikan.

Log menjadi informasi

Satu peristiwa, tiga cara membacanya.

Simulasi dengan delapan peristiwa contoh. Bukan log atau dashboard produksi Telkom.

010203
08:00:01 host=demo-01 event=read status=ok
08:00:02 host=demo-02 event=write status=ok
08:00:03 host=demo-01 event=read status=ok
08:00:04 host=demo-03 event=login status=failed
08:00:05 host=demo-01 event=read status=ok
08:00:06 host=demo-02 event=write status=ok
08:00:07 host=demo-03 event=login status=ok
08:00:08 host=demo-01 event=read status=ok

Format teks masih harus dibaca satu per satu.

timestamp08:00:01
hostdemo-01
eventread
statusok

Peristiwa pertama dipisahkan menjadi field agar dapat dicari dan dikelompokkan.

8Peristiwa contoh

read4

write2

login2

Delapan peristiwa contoh dikelompokkan menurut event: 4 read, 2 write, dan 2 login.

Case file 07Proyek pribadi · 2026

Demo privat · pratinjau tersedia

Integrasi data lingkungan

Pantau Asap

Saya membuat dashboard untuk membaca prakiraan cuaca BMKG, pengamatan PM2.5, dan deteksi hotspot dalam satu ruang kerja. Sumber, lokasi, dan waktu ditampilkan bersama angkanya supaya konteksnya tetap jelas.

Tantangan
Data datang dari beberapa sumber dengan satuan, cakupan wilayah, dan waktu pembaruan yang berbeda.
Yang saya bangun
Integrasi dan validasi sumber, filter wilayah dan waktu, riwayat PM2.5, ekspor CSV/JSON, serta antarmuka responsif dengan animasi cuaca yang bisa dijeda.
Batasan
PM2.5 mewakili stasiun pengamatan, bukan setiap desa. Hotspot adalah deteksi satelit, bukan jumlah kebakaran terkonfirmasi. Model prediksi PM2.5 belum diaktifkan.
  • Python
  • JavaScript
  • Canvas
  • REST API
  • Vercel
